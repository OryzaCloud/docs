To ensure stability, fair usage, and platform security for all customers, the Oryza API applies rate limits and validation constraints.

## Rate Limiting

The Oryza API implements rate limiting per IP address and API key:

| Route Group | Limit | Description |
| :--- | :--- | :--- |
| **Authentication (`/auth/*`)** | 10 requests / min | Protects against brute-force attacks on login and password reset routes. |
| **Client API (`/api/client/*`)** | 240 requests / min | Standard rate limit for server, file, and schedule operations. |
| **WebSocket Console** | 1 active connection / server | Streaming console connection per user session. |

When a rate limit is exceeded, the API responds with HTTP status `429 Too Many Requests`:

```json
{
  "errors": [
    {
      "code": "TooManyRequestsHttpException",
      "status": "429",
      "detail": "Too Many Requests"
    }
  ]
}
```

## HTTP Status Codes

| Status Code | Meaning |
| :--- | :--- |
| `200 OK` | The request succeeded and returned the requested data. |
| `201 Created` | The resource was successfully created. |
| `204 No Content` | The request succeeded and returned an empty body. |
| `400 Bad Request` | Missing or invalid request parameters. |
| `401 Unauthorized` | Invalid, expired, or missing API key or session. |
| `403 Forbidden` | You lack the permissions required to perform this action on the target server. |
| `404 Not Found` | The requested server, database, file, or resource could not be found. |
| `422 Unprocessable Entity` | Field validation failed on submitted body data. |
| `429 Too Many Requests` | Rate limit exceeded. |
| `500 Server Error` | An unexpected internal error occurred on the host node or panel. |
